# 045. Исправления аудита NET1–NET5, пункты1–4

**Дата:** 17ноября2026. [План](../research/networking/roadmap.md), [проверки](../verification/045-network-audit.md).

## Ошибки участника и расхождение мира

Недействительные команды/управление, framing, текст и превышение квот относятся к конкретному peer. Хост закрывает его transport; зритель не останавливает игру, выпадение human фиксируется общей паузой и control revision. Повреждение сообщения не делает запись согласованного префикса незавершённой у оставшихся. `DesyncException` остаётся причиной остановки всего матча, а не удаления неудобного отчёта участника.

Sequence будущего batch проверяется перед потреблением любых batches текущего тика. Иначе после обнаружения ошибки у последнего игрока могли бы потеряться уже изъятые команды здоровых участников. TickInbox хранит декодированные команды вместе с исходными байтами: preflight не добавляет повторный decode, одинаковые/конфликтующие дубли по-прежнему сравниваются побайтно.

## Время жизни подключения в sandbox

Название, каталог/ключевая identity, grant/endpoints и параметры публикации сохраняются в данных текущего матча независимо от удаляемого MatchSetupScreen. Rejoin использует resume credential и сохранённые endpoints; истёкший admission ticket повторно не применяется. Каталог остаётся необязательным. Клиент каталога освобождается после сетевой сессии при выходе из сцены.

## Билеты и удаление регистрации

Ticket expiry = min(issued+30с, lease expiry). Истечение lease больше не удаляет действующее обещание места. Явный Close скрывает игру и закрывает Find/Join/invite/heartbeat, но не может отозвать уже выданную offline capability: её Match ID остаётся зарезервированным до expiry неиспользованных билетов, максимум30с. После этого тот же ID можно зарегистрировать заново. Удержанные записи входят в прежние лимиты каталога; новая неограниченная история не вводится.

## Длительность журнала

Default ReplayLimits.MaximumTicks поднят с100000 до уже поддерживаемого верхнего предела1млн, общего с конечным MatchDescriptor. При минимальной записи двух сторон квота64MiB ограничивает возможную длину раньше1млн тиков; валидный журнал writer больше не отвергается default reader по старой границе. Те же defaults используются inspection, replay, ReplayCheckpoint и проверкой префикса rejoin. Явный более строгий MaximumTicks сохраняется.

Байтовые/коллекционные квоты,15с transfer/restore и форматы wire/journal/runtime snapshot не изменены. Это не обещание восстановления любого большого мира за15с и не durable host recovery. Пункты5–8 аудита остаются следующей работой.
