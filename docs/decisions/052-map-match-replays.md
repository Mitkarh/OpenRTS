# 052. Версия карты в сетевом матче и повторе

**Дата** 18 ноября 2026. [Проверки B6](../verification/052-map-match-replays.md).

Sandbox выбирает skirmish-карты M1, `.ortmap.json` и `.scenemap.json` через общий каталог. Версия параметров `openrts-lobby-v4` связывает ID карты с её `GameplayFingerprint`, ID стартового набора с его каноническим отпечатком и итоговый каталог вариаций с его отпечатком. `ContentHash` в сетевом дескрипторе берётся из базового каталога манифеста, поэтому выбор карты с локальными вариантами юнитов в лобби работает поверх той же установленной игры. `ScenarioHash` связывает точные сериализованные параметры, включая стороны, назначения, туман, темп и правила обзора. Сверка tick-zero мира выполняется прежним протоколом перед готовностью. Порядок стартов задаёт общий compiler. Меню поддерживает до четырёх сторон с выбором из всех кандидатов карты.

Игровой отпечаток сохраняется при смене оформления. Совпадение файлов сцены между участниками для этого не требуется. Каждый Godot-клиент проверяет и открывает свой установленный bundle. Значимые изменения карты, вариаций юнитов и стартового набора отклоняются до игры, даже если их ID совпали. Ресурсы авторской сцены поставляются вместе с картой по правилам проекта. Передача их по игровому протоколу не входит в B6.

Сетевой матч и локальная запись используют тот же StarJournal. Читатель сохраняет прежние параметры `openrts-lobby-v2` и `openrts-lobby-v3`. Новая версия требует совпадающих отпечатков. Для воспроизведения сохраните нужную игровую версию карты и стартового набора. Если в меню установлена более новая карта с тем же ID, архивный артефакт можно указать явно. Godot проверяет зависимости установленной 3D-сцены. Отдельный headless-процесс использует из bundle только игровую проекцию, а обычный `OpenRTS.Headless` остаётся отдельным потребителем карт без зависимости от Network.

## Запись и открытие

- В редакторе **Build and record playtest** проверяет карту и запускает её с выбранными стартами. Управление принадлежит первому активному игроку. Фиксированные fixture-карты записываются с собственной расстановкой и хотя бы одним игроком. Запись принимает поддерживаемые сетевым форматом игровые приказы. Пауза и скорость влияют на показ и расписание.
- В меню матча **Сохранить повтор и выйти** публикует журнал до последнего завершённого тика в `user://network/`. Успешное завершение записывает итоговый хеш и атомарно переименовывает временный файл. Отмена, недопустимый пакет или переполнение записи не публикуют готовый повтор.
- Зарегистрированные карты доступны в меню **Повторы**. Для локальной или архивной карты передайте артефакт и при необходимости манифест либо архивный стартовый набор.

```sh
./tools/dev.sh run --replay=/path/to/match.journal \
  --replay-map=res://artifacts/maps/initial-properties-isometric.ortmap.json

./tools/dev.sh replay /path/to/match.journal \
  --map=artifacts/maps/initial-properties-isometric.ortmap.json
```

Для другого манифеста укажите `--mod=res://game.yaml` в Godot или `--mod=sandbox/game.yaml` в headless. Путь архивного набора задаётся через `--replay-start-set` и `--start-set` соответственно. `replay` проверяет хеш каждого тика и выдаёт итоговый отчёт `OPENRTS_REPLAY`.
