# 041. Главное меню, список игр и общее лобби

**Дата:** 17 ноября 2026. **Статус:** реализовано; [проверки и изображения](../verification/041-game-shell.md). Развивает [NET3/040](040-net3-multiplayer-lifecycle.md); уточняет его ограничения лобби, зрителей и альянсов. Референсы интерфейса — предоставленные пользователем снимки OpenRA и Age of Mythology: заимствован сценарий экранов, сторонние ресурсы/код не перенесены.

## Экраны

Обычный `tools/dev.sh run` открывает главное меню Skirmish / Multiplayer / Настройки / Выход на статической тактической карте. Фон строится из установленной карты без запуска игровой симуляции. Фоновая партия двух ИИ отложена по поручению пользователя.

Skirmish открывает лобби. Multiplayer открывает список реально объявленных LAN-игр с картой, игроками, свободными местами и зрителями, поиском, созданием именованной игры и прямым подключением по IP/port/pin. Отдельный выбор роли «Игрок / Зритель» не кодируется для пользователя числом0. LAN Join выбирает объявленный свободный слот. Публичный интернет-каталог, аккаунты, NAT/relay и поиск через внешний сервис остаются NET5; придуманных записей в списке нет.

В общем лобби слева находятся до4сторон карты: цвет/сторона, Игрок/Открыто/ИИ/Закрыто, единственная фракция OpenRTS, альянс, старт и Ready. Справа — кликабельное превью карты, описание, стартовый набор, видимость и темп игры15/25/40Гц. Каталог карт имеет реальные превью, вместимость, размеры, описания и текстовый поиск. Расширенные параметры содержат сетевой буфер. Личные параметры отображения и полноэкранный режим находятся в «Настройках» главного меню; настройки отображения сохраняются в `user://menu.cfg`.

Host меняет игровые параметры, карту, свободные места, ИИ, старты и альянсы. Гости и зрители видят их в тех же контролах без возможности редактирования. Занятый human-слот нельзя молча закрыть/заменить ИИ; карта с недостаточной вместимостью для подключённых игроков недоступна. Перестановка занятого старта обменивает назначения. Закрытая сторона не создаёт игрока/стартовые объекты, её ID сохраняется для остальных сторон. В Skirmish можно назначить несколько ИИ; доступен существующий supply-профиль. Зрители перечислены отдельно от игровых мест.

## Синхронизация до Start

StarSession protocol2 поддерживает необязательную game-owned recipe≤16KiB и конкретный callback её подготовки. Sandbox использует типизированный MatchSetupOptions: map/start-set ID, fog, D, tick rate и4слота с controller/start/team. Network не зависит от YAML/Content/Godot.

Host получает ConfigureLobby через bounded очередь, только в Lobby. Он проверяет controllers/занятые места, создаёт новый tick-zero мир, меняет descriptor и рассылает recipe, затем новую Revision со снятием Ready всех human. Гость готовит **собственный** мир из установленных карт/контента, сравнивает descriptor digest и World hash и подтверждает recipe digest/hash. Только после подтверждения Host принимает Ready текущей Revision. Устаревший ACK предыдущей recipe игнорируется; чужой hash текущей recipe — ошибка. Ни UI, ни I/O не владеют ECS refs, подготовка/замена/Dispose мира остаются на owner thread. Импортированная конфигурация меняет UI на Godot thread.

В recipe-режиме начальный Hello проверяет rules/content и протокол; выбранные у гостя карта и fog могут отличаться. При отсутствии callback остаётся прежнее точное сравнение descriptor/начального hash. Число protocol-слотов sandbox постоянно4; неиспользуемые слоты закрыты, что позволяет менять карту2↔4 в лобби. Journal StarJournal2 отличает изменённый формат MatchState с количеством зрителей. Старые StarJournal1 явно несовместимы; двухсторонний MatchJournal3 не менялся. Replay по-прежнему требует descriptor и фабрику исходного мира, а не является snapshot/самодостаточным сохранением.

## Зрители с начала матча

Гость с Player0 получает отдельное соединение зрителя, не игровой слот; до8зрителей. Он получает настройки, общий поток команд/control и рассчитывает полный мир. Нельзя Ready/Submit/Pause/Configure от зрителя. Зрители исключены из проверки готовности, ожидания batches и минимального checkpoint ACK. Для их исходящих очередей используется TrySend; заполнение очереди отключает зрителя. Его потеря не объявляет игровую паузу. Завершение зрителей ограничено100мс flush и не требует их terminal ACK.

В sandbox зритель видит полный мир и не получает команд управления. Это обычное lockstep-наблюдение с полной информацией; защищённым/отложенным зрителем его считать нельзя. Подключение посреди матча, reconnect и snapshot/catch-up остаются NET4. Журналы успешного зрителя и игроков совпадают побайтно.

## Фиксированные альянсы

SimulationWorld.SetInitialTeams допускается только на tick0. Ненулевая одинаковая команда означает союз. Combat target acquisition, обычная атака, защита от friendly fire и capture учитывают AreAllied. ИИ исключает союзников и закрытые стороны из целей/исходных направлений. Owner, команды управления, очереди, экономика, транспорт и обзор остаются раздельными; нет общей казны, дипломатии в ходе матча или shared vision.

Team0 сохраняет прежнее FFA-поведение и байты hash. Непустые teams включены в hash отдельной ordinal-записью с тегом−40. Это изменение семантики при явно заданных командах, не скрытая смена базовых golden traces.

## Доступность и пределы

LanGames — необязательное UDP-обнаружение на17772: versioned query, ответы≤2048bytes,≤4ответа/сек, до64записей с TTL6сек. IP берётся из endpoint ответа; метаданные и pin не заменяют независимую проверку личности хоста. Никакой мировой информации discovery не получает. Вход по адресу работает без discovery. TLS/ограничения transport и доступность сервиса не превращаются в доверенный игровой сервер; NET8/NET9 остаются последним выключенным по умолчанию режимом.

Проверены native Godot controls, headless flow и отдельные окна со снимками, совпадение журналов, реальная LAN-пара UDP на loopback, три human+AI+зритель и8human. Физическая сеть разных машин и производительность больших армий этим не подтверждены.
