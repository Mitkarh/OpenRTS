# 043. NET4.2/4.3 — runtime snapshot и возврат участников

**Дата:** 17 ноября 2026. Продолжает [NET4.1](042-net4-replay-recovery.md). [Проверки](../verification/043-net4-runtime-rejoin.md), [живой план](../research/networking/net4.md).

## Состояние мира

`SimulationWorld.CaptureSnapshot` и `RestoreSnapshot(bytes, factory, cancellationToken)` работают на owner thread между завершёнными тиками. Restore создаёт исходный tick-zero сценарий, проверяет его hash, загружает логическое состояние и сравнивает hash границы K. Частичный мир не публикуется и освобождается при любой ошибке. Core предоставляет только allocator/tick/RNG и runtime layers NavigationGrid; зависимость на Gameplay/Network не появляется.

Контейнер ORTS-RUNTIME v1 содержит длину, SHA-256, hash исходного сценария, hash K и runtime payload. Это состояние на K, без исполнения команд0..K. Определения, статические surface/obstacles и callbacks берутся из той же фабрики/установленного контента. Типы CLR, native handles, Frent storage и код из файла не загружаются.

Схемы явно перечисляют поля компонентов и логических систем. RuntimeArchive использует reflection только по этим закрытым схемам, вне горячего тика; добавленное поле компонента требует дополнить схему либо явно назвать исключение. Последовательность полей фиксирована версией контейнера; изменение бинарной схемы требует новой версии. Actors записываются по EntityId, dictionaries/sets — по каноническому кодированию ключей; packed/native порядок не сохраняется. Очереди и порядок пассажиров сохраняются.

Сохраняются allocator/резервы IDs/RNG; пространственное состояние, здоровье, владельцы, приказы/FIFO, движение и навигационные агенты; залпы/windup/cooldown/снаряды, presentation; счета/доходы, производство/платежи/TaskId; стройки/резервы, захват, пассажиры, supply, upgrades, transformations и flight; базовые/эффективные terrain layers; fog retention, sensor grants, contact/building knowledge и локальные IDs контактов. События завершённого тика повторно не выдаются.

Навигационные поля восстанавливают именно slots, goals, FIFO cursors и бюджет. Их distance/cost arrays и shared trees пересчитываются из неизменного terrain без продвижения симуляции и с отменой; корень weighted group tree сохраняется, включая fallback. Motion/air/sensor indexes, sorted queries и scratch пересобираются. Fog сохраняет активное incremental coverage/group state; временные Pending/Seen/Sorted не сохраняются. Экспериментальные будущие системы обязаны получить свою схему до использования snapshot.

Stateful регистрации реализуют `IRuntimeSnapshotMechanic`: отдельные bounded readers/writers общего состояния и состояния actor. ID/version регистрации входят в исходную identity мира. Без reader сохранение явно отвергается; старый replay recovery остаётся доступным. Immutable production/scoring configuration сохраняет действующий контракт. Память AI policy вне World не выдаётся за часть снимка: replay применяет готовые команды, а reconnect не пересоздаёт хост и его планировщиков. Для переноса всего хоста нужен отдельный game-owned save/reset контракт.

## Возврат и зрители

StarProtocol v3 добавляет role-bound resume credential, connection epoch и recovery frames. Хост выдаёт случайный 256-bit token по pinned TLS. Credential привязан к Match/Player; live слот или уже восстанавливающийся слот нельзя занять второй раз. Старый Peer/Pipe закрывается, входная последовательность нового соединения начинается отдельно; последовательность **согласованных** команд продолжается из журнала.

1. После потери клиента хост фиксирует None/общую паузу на K по NET3. Уполномоченный возврат также ставит на паузу матч, продолженный с ИИ.
2. Хост проверяет token/epoch/контент/роль и исходный сценарий. TLS/Hello handshakes выполняются вне owner в очереди до8; незавершённый handshake не останавливает тики.
3. Owner снимает runtime snapshot и префикс журнала до K. Передача выполняется вне owner chunks по32KiB с backpressure; остальные peers получают heartbeat. Во время admission нельзя снять общую паузу или переназначить ИИ.
4. Клиент проверяет порядок, размеры и digests, исходную recipe, структуру префикса, его последовательности/control и равенство hash snapshot/журнала. Мир восстанавливается сразу на K. Префикс нужен для общего полного журнала, а не для исполнения симуляции от0.
5. Клиент подтверждает K/hash. Хост досылает controls, появившиеся за время передачи, выдаёт новую эпоху/token, фиксирует Human/Connected/Ready на том же K и публикует изменение всем peers. Для K+1..K+D−1 новой стороны согласованы пустые inputs, первый новый input относится к K+D.
6. Матч остаётся на общей паузе до Resume. После продолжения журналы восстановленных и оставшихся peers совпадают побайтно и воспроизводятся от0.

До первого проверенного Hash от новой connection предыдущий credential сохраняется как fallback: разрыв при доставке нового токена не лишает игрока возможности повторить возврат. Затем предыдущий token/epoch отзывается. Токен не печатается в ToString и не пишется в журнал. Новый клиент может предъявить credential через API; sandbox хранит его только в памяти и показывает «Вернуться в матч» после разрыва. Автоматического хранения секрета на диске нет.

Зритель может войти и после Start на **уже установленной общей паузе** без игрового credential; анонимный запрос во время Playing отвергается и не ставит игру на паузу. Зритель получает полный мир, не отправляет команды и не голосует за тики. Бесшовная догонка наблюдателя при непрерывно идущей игре остаётся продолжением для NET6/NET7.

## Пределы

Одновременно допускаются до2 recovery transfers; снимок одной границы разделяется между ними. Snapshot payload ≤64MiB, коллекции payload имеют учётный бюджет256MiB (память исходной фабрики, ECS и derived navigation ограничивается отдельными бюджетами движка), суммарные коллекции≤16Mi элементов, вложенность≤32; custom section≤1MiB. Префикс журнала≤64MiB/100000тиков по текущим ReplayLimits. Размеры/offsets/flags/duplicates/trailing bytes проверяются. Передача≤15с, восстановление/разбор≤15с, admission≤30с; отмена достигает builtin навигационных перестроений. Произвольный callback игры обязан сам соблюдать контракт отмены/квот.

Это прямой клиентский lockstep. SHA-256 проверяет целостность, не удостоверяет честный результат матча. Host migration, восстановление произвольной внешней AI policy, дисковый индекс checkpoints для быстрых replay seeks и нагрузка10000+ в этом срезе не объявляются готовыми. Доверенный фильтрующий сервер остаётся последней дополнительной опцией NET8/NET9, выключенной по умолчанию.
