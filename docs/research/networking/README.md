# Сетевой слой OpenRTS

**Дата:** 16 ноября 2026. **Статус:** NET1 реализован как конечный headless lockstep двух клиентов; [контракт037](../../decisions/037-net1-direct-lockstep.md), [проверки](../../verification/037-net1.md). UI и защищённый сервер ещё отсутствуют.

Поручение пользователя: сначала прямой обмен между клиентами с расчётами на них; позднее отдельный доверенный сервер для поиска игр, хранения истинного состояния и выдачи клиентам только разрешённых сведений. Основная реализация ведётся в [OpenRTS.Network](../../../src/OpenRTS.Network/README.md). Это явное основание создать модуль сейчас, пересматривающее прежнее «не создавать Network заранее».

## Результат исследования

Предлагаются два режима исполнения с общей семантикой игровых намерений, но разными правилами продвижения мира и выдачи данных:

1. **Прямой lockstep.** Для первого матча два участника обмениваются закрытыми пакетами команд на будущие тики; каждый считает полный мир. Отсутствие пакета останавливает продвижение. Это соответствует существующей детерминированной симуляции и не требует рассылать позиции 10000 объектов.
2. **Доверенный сервер.** Только сервер считает истинный мир, проверяет команды и строит наблюдения отдельно для каждого получателя. Клиент хранит реплику разрешённых знаний, интерполирует и, при необходимости, предсказывает только разрешённые данные. Полный lockstep-журнал и полный снимок ему не выдаются.

Сервис поиска матчей, relay и авторитетный сервер симуляции — разные роли, даже если первоначально живут в одном процессе. Перенос пересылки команд на отдельную машину сам по себе не скрывает мир от клиентов. Обоснование: [разбор референсов](references.md), особенно различие Recoil и Mindustry. Конкретные контракты — [проект алгоритмов](design.md), порядок реализации и критерии — [дорожная карта](roadmap.md).

В `Filter` сохраняются `Grid`/`BaseGrid` истинного мира. `AcquireLatest(0)` даёт общий кадр, а при отсутствии списка FogPlayers фильтрация не выполняется. Поэтому сериализация существующего lease целиком не является безопасным серверным протоколом. Полный snapshot/restore пока отсутствует по текущей архитектуре; rejoin с контрольной точки зависит от отдельной работы над сохранением.

## Что сравнивалось

OpenRA выбран за C#, разделение графического/сетевого тика и близкий домен; 0 A.D. — за барьеры команд и восстановление подключения; Recoil — за массовую RTS, dedicated relay и воспроизведение потока; Mindustry — как RTS-гибрид с передачей состояния по видимости. Последний отличается наличием управляемого игроком персонажа, поэтому его модель доверия к координатам не переносится в OpenRTS.

Метод: статические трассы выбранных функций, проверка вызываемых ветвей, официальная документация Recoil. Это направленное сравнительное исследование, не аудит безопасности этих проектов. Версии, ссылки и пределы чтения находятся в [реестре источников](references.md). Никакой GPL код, переводы функций или сторонние зависимости в MIT модуль не перенесены.

## Основные развилки

- Два клиента сначала связываются непосредственно; для 3+ участников предлагается звезда через клиент-хост. Хост остаётся участником с полным миром, а не доверенной стороной.
- Для первого LAN/IP прототипа предлагается TCP с ограниченным framing. Для WAN и state replication транспорт выбирается после измерения head-of-line задержек; собственный reliable UDP заранее не строится.
- Ранний replay — initial match descriptor + команды от тика0. Контрольные точки нужны позднее для дешёвого rejoin, перемотки и восстановления сервера.
- Защищённый режим требует серверных расчётов навигации, боя, экономики, сенсоров, RNG и всех взаимодействий со скрытыми объектами. Клиентские расчёты допустимы как подсказки/предсказание без права менять истину.
- Переход будет отдельным сетевым режимом, а не обещанием совместимости первого wire-протокола. Версии согласуются при подключении, несовместимые режимы отклоняются.

Следующая работа — **NET2: UI, realtime pacing, испытания WAN и аутентифицированный канал**. NET1 работает в headless-стенде через loopback TCP с барьером тика и desync-проверкой. Подробный backlog и ограничения каждого этапа: [roadmap](roadmap.md).
