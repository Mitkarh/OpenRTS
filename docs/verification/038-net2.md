# 038. Проверки live direct matches (NET2)

**Дата:** 16 ноября 2026. **Профиль:** macOS / Apple M3 Max, .NET10.0.105, Godot4.7.2 Mono, TCP/TLS loopback. [Контракт](../decisions/038-net2-live-direct-matches.md).

- Сборка решения прошла без предупреждений/ошибок.
- 16 сетевых проверок: прежние framing/sequence/barrier/replay/desync + live TLS, pacing, очередь полного ввода, Leave/replay, отклонение неверного fingerprint, сохранение дополнительных полей production/transform/contact/placement.
- 6 существующих проверок `--filter=session` прошли; старый Godot `--verify-match-setup` прошёл. ToCommand не меняет игровую семантику/хеши.
- `./tools/dev.sh verify-network` импортирует ресурсы и запускает два настоящих Godot-процесса через экран host/join с разными локальными player IDs. Проверяет локальную ownership policy, отправляет rally/stop/production, держит локальное меню открытым как минимум4сетевых тика, затем выполняет Leave. Оба процесса завершаются с одним hash и независимо воспроизводят полный skirmish-журнал offline с исходными map/fog/sensor settings. Completion публикуется после закрытия журнала.
- Оконный прогон `python3 tools/verify_network.py <godot> --visible --output=<path>` выполнен при900×700. Меню и очередь производства визуально проверены по [кадру](038-net2-menu.png). Захват выполняется на Godot thread после ProcessFrame с ForceDraw, чтобы occluded окно тоже давало актуальный кадр. Сам сетевой runtime не вызывает графические API.

Итоговый hash одного оконного прогона: `BF2B29CBA8EA1CE0C2111C90F1DC93C6EBEC042DD420BBC88A5C0DE0F3E51A6E`. Тик ввода/Leave задаёт live UI, поэтому hash между отдельными запусками может различаться; внутри каждого матча peers обязаны совпадать.

## Пределы

Это LAN/UI срез NET2, не готовность WAN. Не проверены две физические машины, NAT, packet loss/jitter profiles, cross-OS/CPU determinism и численные бюджеты input latency/трафика. Строгий hash barrier пока добавляет RTT на каждый тик. Следующая работа NET2 — pipeline/input delay/hash cadence и воспроизводимые RTT/потери/slow-consumer измерения, затем выбор transport по результатам. Полного reconnect, общего pause/surrender policy и host migration пока нет.

Полный старый игровой suite повторно не выполнялся: при NET1 уже подтверждены8падений исходного HEAD, описанные в [проверке037](037-net1.md). В этой работе выполнены релевантные session/UI регрессии; игровые golden traces не обновлялись. Codec version1/journal1 не читаются version2; межверсионная совместимость не заявлена.
